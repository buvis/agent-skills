# Recognize every pipeline frontmatter key and the lane path rule

Source: the claude-autopilot backlog review of 2026-09-14 (`/Users/bob/git/src/github.com/buvis/claude-autopilot/dev/local/audit-results/backlog-review-2026-09-14.md` § Gaps) and discovery 00203 there (§ Nice to have, the `create-prd` and `review-prd-backlog` follow-ups). Advisory discovery gate skipped: every key's semantics is sourced from the installed plugin or a reviewed PRD, and the edits are list lines.

## Problem

The autopilot pipeline reads twelve PRD frontmatter keys; `skills/create-prd/SKILL.md` § Optional frontmatter fields (`:88-116`) lists seven, and `skills/review-prd-backlog/SKILL.md:67` (lens A) names the same seven as the only recognized fields and flags anything else. Five are missing. Two are live in the installed plugin today (autopilot 0.5.2): `pause_on_ambiguity: true` (the Phase 0 opt-in that makes a Phase 2 ambiguity stall instead of assume; `run-autopilot/references/phase-build.md:130`) and `eligibility: <command>` (read by `autopilot select` at pick time, `run-autopilot/cli/eligibility.py`; a failing command skips the PRD, `phase-build.md:70`). Three land with the batch reviewed on 2026-09-14: `plan_expansion: allow` (autopilot PRD 00189), `session_model: sonnet | opus` (PRD 00200) and `lane: solo | fast-track | full` (PRD 00204). An author who uses any of the five learns nothing from `create-prd`, and the gate raises "unrecognized field" on a key the loop honours.

The same batch also fixes how a PRD's paths are read. PRD 00204's classifier takes a PRD's named paths only from the `### Repository Structure` tree and the `**Location**:` spans, and PRD 00206's card renderer refuses a path that does not resolve from the repo root and any glob; a fast-track card's file allowlist is exactly that set. Three PRDs in the reviewed backlog would have failed the lane for path reasons alone: one wrote skill-relative paths (`cli/test_loop.py` for `skills/run-autopilot/cli/test_loop.py`), one wrote a glob (`agents/*.md`), one omitted a test file its own task edits. `create-prd` step 3 says nothing about it, so the next PRD written for the lane repeats one of the three.

## Solution

Extend the two lists to the twelve keys with the same one-bullet shape the existing entries use, and add one **Path rule** paragraph to `create-prd` step 3 beside the Unattended, Premise and Metric rules. Lens A of the gate recognizes the twelve keys with their valid values; lens C checks the Path rule. One prose test pins both skills to the same key set so they cannot drift apart again. Nothing here changes the templates under `assets/`.
