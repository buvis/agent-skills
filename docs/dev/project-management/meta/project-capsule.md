## Key Invariants

- `skills/` is the only directory `braid` scans and projects to other hosts
  (`~/.agents/skills`, `~/.claude/skills`). A `SKILL.md` placed there is
  advertised as runnable on Claude Code, Codex, and Copilot alike — a
  half-implemented skill (prose without the code it describes) must live
  under `docs/plugin-skills/<name>/` instead, or it gets routed to and fails
  on hosts without the backing plugin.
- Every path inside a `SKILL.md` must resolve on all hosts: same-skill files
  use `~/.agents/skills/<name>/...`, never `${CLAUDE_SKILL_DIR}` (Claude-only)
  and never a bare `/Users/<name>/...` (single-machine). `${CLAUDE_SKILL_DIR}`
  is expanded by Claude Code before the model even reads the file, so a
  session that writes rendered text back to disk destroys the placeholder and
  bakes in an absolute path — this already happened to `create-skill`
  (fixed 2026-08-26).
- This repo is public: no personal paths, usernames, hostnames, employer
  names, or private project names, including in examples.
- Working documents moved from `dev/local/` to `docs/dev/project-management/`
  (temporary assets to `docs/dev/tmp/`) in cdcb888; any `dev/local/` path in
  older notes is pre-move. `docs/dev/project-management/meta/` is the only
  home for the capsule/decisions/keeper files
  (root went directories-only 2026-08-27 per `~/.claude` PRD 00139); an
  unmigrated store may still carry a root copy, so code that reads keepers
  checks `meta/` first and falls back to root.

## Architecture Decisions

- Skills are portable-first: the repo is the canonical source, `~/.agents/skills`
  is a generated symlink farm (`braid`), and Claude gets a second-hop link via
  `~/.claude/skills`. Compatibility classes (`compatibility:` frontmatter) say
  whether a skill runs everywhere, is a compat copy of a Claude plugin skill
  (skipped by `braid` on the way to Claude), or is a documentation-only copy.
- `docs/plugin-skills/` is deliberately outside `skills/` so no host discovers

## Component Boundaries

- `bin/braid.py` (installed as the `braid` CLI) composes sources and projects
  to hosts; it owns the symlink farm and is the only thing that should ever
  create/remove those links.
- `skills/create-skill/scripts/validate_skill.py` is the compliance gate run
  on every touched skill before commit.
- `skills/*/scripts/` hold each skill's executable logic and its
  `test_*.py`/shell suite, collected by `uv run pytest` and (per recent CI
  failures below) a "run every skill's shell suite" CI step.
- `skills/distil-memory/` is being built in three PRD slices against one
  seam: `funnel.judge(prompt, tier)` is the ONLY route to a model in the whole
  skill (`_MODEL_FOR_TIER = {"cheap": "haiku", "strong": "sonnet"}`, 120s
  `subprocess.run` on the `claude` CLI, raises `RuntimeError(stderr)` on
  non-zero). Slice 2 (00008, `distil.py`/`dedup.py`/`proposal.py`) must call
  the strong tier through that function and define no second path; its tests
  inject a stub judge and must never reach the default. The other consumable
  from slice 1 is `funnel.Slice` (frozen dataclass: `text`, `transcript`,
  `line_no`, `marker`) — the evidence block 00008 attaches comes straight off
  those fields, and `triage()` shows the injection idiom
  (`judge: Callable[[str, str], str] = judge`).
- `ruff` deliberately excludes `skills/` and `docs/` (`extend-exclude` in
  `pyproject.toml`), so skill scripts are lint-free by design — `uv run
  pytest` plus `validate_skill.py` are the whole gate for a skill change.
- `skills/use-qwen/` is the local-model dispatch and qualification surface.
  `scripts/qwen-run.sh` dispatches through the `pi` agent (`-P` pins the
  provider, `-m` the model id, `--preflight` demands a real 1-token
  completion, `--approved-only` restricts to `scripts/approved-models.txt`);
  `scripts/run-eval.sh` automates runbook steps 2/3/5 over a 6-line TSV
  manifest (`<prompt-file>\t<verify-cmd>`, exactly 6 lines or it refuses) and
  writes the evidence log to `dev/local/audit-results/qwen-eval-<slug>-<date>.md`;
  `scripts/promote-default.sh` writes `scripts/default-model.txt` and
  regenerates the fact-only Default bullet in `SKILL.md`. Trust boundary:
  `approved-models.txt` is what autopilot's `--approved-only` dispatches
  trust; the SKILL.md Model Selection bullet is where the trust SCOPE
  (single-file-only vs multi-file) is documented in prose, and nothing
  machine-reads that scope today. The Sonnet counterpart lives in BOTH places:
  `skills/use-sonnet/scripts/sonnet-run.sh` in this repo (with
  `test_sonnet_run.sh` beside it) is the canonical source, and the autopilot
  plugin ships its own twin at
  `<autopilot-plugin-root>/skills/use-sonnet/scripts/sonnet-run.sh`. `-y` for
  unattended edits, `-o` to capture output. Corrected 2026-09-07: earlier
  passes recorded it as plugin-only, which is wrong and would have made

  proof it's the one executing. Relevant if a plugin (e.g. aegis, loupe) seems
  to misbehave in a way its CHANGELOG says was already fixed.
